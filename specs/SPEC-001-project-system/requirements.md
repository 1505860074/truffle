## 1. 背景与目标

当前 Truffle 是「单文档 + 全局会话」模式：

- 图片通过文件库引用外部绝对路径，项目关闭后不保留图层、历史、选区等状态；
- AI 对话保存在 `%APPDATA%\Truffle\session.json`，全局只有一份（`src/truffle/core/session.py:93`）；
- 窗口布局等少量状态保存在全局 `config.json`；
- 启动后直接进入主窗口（`src/truffle/main.py:42` → `MainWindow`）。

本次目标：

1. 以「项目」作为保存和读取的基本单位；
2. 项目保存导入的图片、每张图片的图层像素、操作树/历史、参数、选区/变换、文件库列表、项目级 AI 对话、窗口布局等；
3. 打开软件后先完成配置/登录，再进入独立的「项目加载页」；
4. 用户在项目页新建或打开项目后，才进入主界面；
5. 关闭主窗口后回到项目页，而不是直接退出软件；
6. 项目文件为单文件 `.truffle`，便于备份、移动和分享。

## 2. 术语

- **项目**：一次修图工作的完整容器，对应一个 `.truffle` 文件。
- **项目页 / 项目加载页**：软件启动后、进入主界面前的独立页面，用于新建、打开、导入、管理项目。
- **默认目录**：新建项目默认保存到的目录，默认 `文档\Truffle Projects`，可在设置中修改。
- **最近项目**：用户打开过或导入过的项目路径记录，可能位于默认目录之外。
- **每图状态**：某张图片自己的图层、历史/操作树、参数、选区、变换、视图状态。
- **项目级对话**：整个项目共享一份 AI 对话上下文，不随图片切换而切换。
- **操作树**：历史面板中的步骤列表（工具、裁剪、液化、图层操作等）及其参数。
- **封面**：项目页卡片上显示的缩略图。

```
启动 Truffle（Truffle.bat 或 scripts\run.bat）
        │
        ▼
加载全局配置、主题、语言
        │
        ├─ 大模型未配置？ ──是──→ 弹出大模型设置窗口
        │                              │
        │                              └─ 完成后继续
        │
        ├─ 开启了强制登录且未登录？ ──是──→ 弹出登录/注册窗口
        │                                          │
        │                                          └─ 成功后继续
        ▼
显示「项目加载页」（独立窗口）
        │
        ├─ 新建项目 ──→ 输入名称/选择位置 ──→ 创建 .truffle ──→ 打开主窗口
        ├─ 打开最近/默认目录项目 ──→ 校验文件存在 ──→ 打开主窗口
        ├─ 导入 .truffle ──→ 校验格式 ──→ 原地打开并加入最近 ──→ 打开主窗口
        ├─ 重命名/删除/搜索/排序/切换视图 ──→ 留在项目页
        └─ 关闭项目页 ──→ 退出软件
```

图 2：主窗口关闭与返回项目页

```
主窗口收到关闭事件
        │
        ├─ 有未保存改动？ → 立即保存（失败则提示，不静默丢弃）
        ├─ 保存项目布局/窗口几何
        ├─ 关闭并销毁主窗口
        ▼
重新显示项目页并刷新列表/封面/修改时间
        │
        └─ 用户再次选择项目 → 重新创建主窗口
```

关键约束：

- **没有项目就不创建主窗口**。主窗口只能由项目页通过「打开项目」创建。
- 项目页在配置/登录之后出现；配置/登录仍在项目页之前。
- 主窗口关闭是「关闭项目」，不是「退出软件」；退出软件只能从项目页关闭，或由项目页明确提供退出入口。

## 5. 项目加载页设计

### 5.1 窗口形态

- 独立顶层窗口，不与主窗口共用同一个 `QMainWindow` 实例。
- 建议默认尺寸 1200×800，可记忆大小；也可最大化启动。
- 使用现有主题系统（`src/truffle/ui/theme.py`）和中英双语（`src/truffle/ui/i18n.py`）。
- 关闭项目页（无打开项目时）即退出软件（D18）。
- 项目页顶部提供「设置」「账号状态」「社区」入口（见 D30）。

### 5.2 布局

```
┌──────────────────────────────────────────────────────────────┐
│ Truffle     [搜索项目…]        [排序▾] [卡片/列表] [设置]     │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐              │
│  │ 封面   │  │ 封面   │  │ 封面   │  │  +     │              │
│  │ 项目名 │  │ 项目名 │  │ 项目名 │  │ 新建   │              │
│  │ 修改时间│  │ 修改时间│  │ 修改时间│  │        │              │

│ [导入项目]                        最近项目 X 个 · 默认目录 …  │
└──────────────────────────────────────────────────────────────┘
```

### 5.3 卡片内容

每张卡片至少显示：

- 封面图（见第 8 节）；
- 项目名称；
- 最后修改时间；
- 来源标记（默认目录 / 最近项目 / 外部位置），可用小徽标或次要文字；
- 文件缺失状态：整卡降低透明度、显示警告图标或「文件不存在」文字。

列表视图至少包含：封面小图、名称、修改时间、完整路径、状态（正常/缺失）。

### 5.4 数据来源与合并规则

项目页的数据 = **默认目录扫描结果 ∪ 最近项目记录**：

1. 扫描默认目录下的 `*.truffle`；
2. 读取保存的最近项目路径列表；
3. 按规范化绝对路径去重；
4. 合并后按修改时间倒序（默认）或名称排序；
5. 每次进入项目页、从主窗口返回项目页、手动刷新时，重新检查每个项目文件是否存在；
6. 不存在的项目保留在列表中并标灰，不自动删除（D20）；
7. 用户点击缺失项目时弹出提示，给出「移除记录」与「取消」；不直接崩溃或静默忽略；
8. 最近项目记录保存完整路径，不能只保存文件名。

建议把最近项目单独存到 `%APPDATA%\Truffle\projects.json`，不要塞进 `config.json`；已采用独立文件（见 D28）。

### 5.5 项目页操作

| 操作 | 触发方式 | 行为 |
| --- | --- | --- |
| 新建项目 | 顶部/空状态按钮、卡片区的「+」 | 打开新建项目对话框（5.6） |
| 打开项目 | 单击卡片/列表行 | 校验存在性 → 打开主窗口 |
| 导入项目 | 底部按钮 | 选择 `.truffle` → 校验 → 原地打开并加入最近（D16） |
| 重命名 | 卡片右键菜单 | 重命名 `.truffle` 文件与 `manifest.json` 中的 `name`，更新最近路径 |
| 删除 | 卡片右键菜单 | 二次确认 → 移到回收站 → 从最近记录移除（D19） |
| 设置封面 | 卡片右键菜单 | 见第 8 节 |
| 在资源管理器中显示 | 卡片右键菜单（建议） | 打开项目所在文件夹并选中文件 |
| 移除记录 | 缺失项目的提示/右键 | 只删除最近记录，不动磁盘文件 |
| 搜索 | 顶部搜索框 | 按项目名和路径不区分大小写过滤 |
| 排序 | 顶部排序下拉 | 修改时间倒序/正序、名称升序/降序 |
| 视图切换 | 顶部按钮 | 卡片网格 ↔ 列表；记住选择（D10） |

### 5.6 新建项目对话框

字段：

- **项目名称**：必填；去除首尾空格；不能为空；不能包含 Windows 文件名非法字符 `\ / : * ? " < > |`；建议限制长度 1~80。
- **保存位置**：下拉框，默认选中「默认目录（文档\Truffle Projects）」；另一项为「选择其他位置…」，打开目录选择框。
- 文件名自动为 `<项目名称>.truffle`。
- 若同目录已存在同名文件：不得静默覆盖；提示用户改名或选择其他位置。
- 创建成功后：生成空项目 → 立即进入主窗口（空画布/空文件库）→ 加入最近项目。

默认目录为空或不可写时，提示用户并允许改选位置。

## 6. 项目文件格式（`.truffle`）

### 6.1 基本约束

- `.truffle` 是一个 ZIP 容器，扩展名固定为 `.truffle`。
- ZIP 根目录必须有 `manifest.json`，包含 `schema` 版本号。
- 所有内部路径使用 `/`，禁止绝对路径和 `..` 路径；读取时必须做 ZIP 路径穿越校验。
- 项目名称、时间、版本等元数据写入 `manifest.json`；不要依赖文件名作为唯一真相（文件名可被用户改）。
- 保存必须原子化：先写同目录临时文件（如 `xxx.truffle.tmp`），成功后再 `os.replace` 覆盖原文件；保留一份 `.truffle.bak`（见 D27）。
- 写入失败不能让原项目损坏；失败时提示并保留内存状态。

### 6.2 建议的 ZIP 结构

图 3：项目文件内部结构

```
my-project.truffle (ZIP)
├─ manifest.json
├─ chat.json                      # 项目级 AI 对话
├─ sources/                       # 原始导入文件，保留原始格式/字节，便于溯源
│  ├─ img_0001.jpg
│  └─ img_0002.png
├─ images/
│  ├─ img_0001/
│  │  ├─ state.json               # 该图的图层元数据、操作树、选区、变换等
│  │  ├─ layers/
│  │  │  ├─ 0001.png              # BGRA 图层像素
│  │  │  ├─ 0001.mask.png         # 可选：图层蒙版（灰度）
│  │  │  └─ 0002.png
│  │  ├─ steps/                   # 操作步骤中携带的数组（蒙版、液化笔划等）
│  │  │  └─ 0001_mask.png
│  │  └─ selection.png            # 可选：当前选区蒙版
│  └─ img_0002/
│     └─ ...
└─ previews/
   ├─ cover.png                   # 项目页封面
   ├─ tile_1.png ... tile_4.png   # 可选：4 图拼合封面素材
   └─ placeholder.png             # 可选
```

建议说明：

- `sources/` 保存用户导入时的原始字节与扩展名，用于“原图”与 EXIF 溯源；
- `images/<id>/layers/*.png` 保存编辑后的 BGRA 像素；不要只保存最终合成图，否则无法恢复图层；
- `steps/` 用于保存 `Step.data` 中的 ndarray（例如工具蒙版、液化笔触）；PNG 只适合 uint8 蒙版，其他数组可用 `.npz`，实现时统一约定；
- `previews/` 可由保存流程重新生成，允许缺失并用占位图。

      "name": "背景",

## 7. 保存内容清单与保存流程

### 7.1 必须保存的内容（D3）

| 内容 | 保存位置 | 说明 |
| --- | --- | --- |
| 导入的原始图片 | `sources/` | 添加后立即复制（D21） |
| 每图的图层像素 | `images/<id>/layers/` | BGRA PNG |
| 图层元数据 | `images/<id>/state.json` | 名称、显隐、透明度、混合模式、蒙版、锁定 |
| 操作树与参数 | `images/<id>/state.json` 的 `steps` / `pointer` | 工具、裁剪、液化、图层步骤等 |
| 当前选区 | `images/<id>/selection.png` + state | 每图独立 |
| 自由变换状态 | `images/<id>/state.json` 的 `transform` | 每图独立 |
| 文件库列表 | `manifest.json` 的 `library` | 顺序、显示名、来源 |
| 当前活动图 | `manifest.json` 的 `active_image_id` | 打开项目时恢复 |
| 项目级 AI 对话 | `chat.json` | 整个项目共享一份（D15） |
| 窗口布局 | `manifest.json` 的 `layout` | 项目级保存（D3） |
| 封面 | `previews/cover.png` | 见第 8 节 |

### 7.2 保存触发

图 4：保存触发与执行流程

```
项目处于打开状态
        │
        ├─ 定时器到点（默认 60s） ──┐
        ├─ 用户按 Ctrl+S ──────────┤
        ├─ 菜单「保存」 ───────────┤
        ├─ 关闭主窗口 ─────────────┤──→ 有脏数据？ ──否──→ 跳过
        ├─ 切换活动图片前 ─────────┤           │
        └─ 切换/关闭项目前 ────────┘          是
                                                ▼
                                     收集内存状态（锁住 UI 或快照）
                                                │
                                                ▼
                                     写临时文件 → 校验 → 原子替换
                                                │
                                     ├─ 成功 → 清除脏标记 / 更新时间 / 刷新封面
                                     └─ 失败 → 保留脏标记，提示用户
```

要求：

- 默认间隔 60 秒；设置中可调 30 秒~10 分钟；0 表示关闭定时保存（D5）。
- 手动保存快捷键 `Ctrl+S`；菜单项「保存」。
- 自动保存不应在用户正在拖拽/正在执行不可中断操作时破坏状态；实现可在主线程快照后保存，或使用后台线程并加锁，但不能让 UI 长时间卡死。
- 保存期间状态栏显示「保存中…」，成功后显示「已保存 HH:MM:SS」，失败显示错误。
- 关闭主窗口、切换项目、退出前必须强制保存一次。
- 无脏数据时自动保存直接跳过，避免无谓写盘。

## 8. 封面

### 8.1 已确认模式

D23 确认需要支持以下封面来源：

1. **当前活动图（默认）**：保存时用当前活动图片的当前合成结果生成封面；
2. **自定义封面**：用户可为项目选择一张图片作为封面；
3. **4 张活动图缩略图拼合**：用 4 张图片的缩略图拼成一张封面；
4. **导入的第一张图**：固定使用项目文件库中第一张导入图片。

### 8.2 建议行为

- 默认模式为「当前活动图」。
- 设置中提供「默认封面方式」，新建项目继承该默认值。
- 项目页卡片右键菜单提供「设置封面…」，可对单个项目覆盖默认方式。
- 自定义封面图片应复制进项目（放进 `previews/`），不能只引用外部路径。
- 4 图拼合取最近编辑的 4 张、2×2 排列（见 D38）。
- 封面建议尺寸 640×480 或 640×360，保持比例并留白；4 图取最近编辑的 4 张、2×2（见 D38）。
- 封面缺失或损坏时显示占位图（项目名首字母/纯色块），不能显示破图。

## 9. 多图片状态模型

### 9.1 归属规则（D15）

- 文件库中的每张图片对应一个稳定的 `image_id`（如 `img_0001`）。
- 每张图片拥有独立的：图层栈、操作树/指针、参数面板状态、选区、自由变换、视图状态。
- **整个项目只有一份 AI 对话**；切换图片不切换对话。
- 切换到某张图片时，必须恢复到该图片上次离开时的状态，包括历史面板指针。
- 添加图片后立即复制原始文件进项目（D21）；即使用户不保存就关闭，项目内副本仍应完整（除非用户明确删除）。

图 5：图片切换时的状态恢复

```
用户点击文件库缩略图 img_0002
        │
        ├─ 当前 img_0001 有未保存的每图状态 → 写回内存状态表（必要时触发项目保存）
        ├─ 从项目载入 img_0002 的 state.json / 图层像素
        ├─ 恢复图层栈、操作树指针、参数、选区、变换、视图
        ▼
主界面显示 img_0002 的状态
（AI 对话保持不变，属于项目级）
```

### 9.2 删除图片

从文件库删除图片时的磁盘行为见 D40：从项目移除并删除项目内副本。可选方案：

- 从项目移除并删除项目内副本（推荐，保持项目自包含且不臃肿）；
- 仅从文件库移除，保留项目内副本（可恢复，但项目会变大）。

### 9.3 现有代码适配点

- `FileLibrary` 目前只保存外部绝对路径（`src/truffle/ui/file_library.py:187`）；需要改为保存 `image_id` + 显示名，并通过项目资源解析真实路径。
- `MainWindow._open_from_library` 目前直接 `self.doc.load(path)`（`src/truffle/ui/main_window.py:887`），切换图片会丢弃上一张文档状态；需要改成「保存当前每图状态 → 载入目标每图状态」。
- `LayerDocument` 目前是单个文档实例（`src/truffle/ui/main_window.py:92`），建议改为每图一个实例或一个可缓存的状态表。
- 从系统剪贴板粘贴图片时，目前写临时文件（`src/truffle/ui/main_window.py:975`）；项目模式下应直接生成项目资源。

## 12. 已解决的行为细节（实现依据）

以下问题已与用户确认，实现时直接按此执行；第 3 节表格是摘要，本节是补充说明。

- **历史持久化（原 Q1）**：每张图保存最近 N 步完整快照，重新打开后可在 N 步内回退；操作树只读展示，不允许重开后修改/删除历史步骤。
- **历史步数（原 Q1 补充）**：N 默认 20，可设 0~100；全局设置提供默认值，项目可单独覆盖；0 表示不保存历史（操作树也不保留）。
- 封面建议尺寸 640×480 或 640×360，保持比例并留白；4 图取最近编辑的 4 张、2×2（见 D38）。
- **主窗口关闭（原 Q3）**：一律保存并回项目页；移除「每次询问 / 最小化 / 直接退出」旧选项。退出软件只能从项目页或项目菜单的「退出软件」进行。
- **删除文件库图片（原 Q4）**：从项目移除并删除项目内副本，同时删除该图的图层、历史、选区等状态；删除前二次确认。
- **配置/登录取消（原 Q5）**：允许进入项目页，但保留 AI 对话栏、禁用发送，并提示用户去配置/登录；本地参数面板和工具不受影响。
- 另存为复制成新项目并切换（见 D27）。
建议把最近项目单独存到 `%APPDATA%\Truffle\projects.json`，不要塞进 `config.json`；已采用独立文件（见 D28）。
- **默认目录变更（原 Q8）**：只切换扫描目录，不迁移旧项目；最近记录保留，用户仍可打开旧目录项目。
- 项目页顶部提供「设置」「账号状态」「社区」入口（见 D30）。
- **长任务自动保存（原 Q10）**：到点若 AI/工具正在后台跑长任务，跳过本轮；任务结束后立即补存。
- **封面作用域（原 Q11）**：全局设置提供默认封面方式，项目右键菜单可单独覆盖。
- **视频（原 Q12）**：本期只支持图片项目，视频保持现有独立功能，不进入项目模型。
- **`.truffle` 文件关联（原 Q13）**：注册文件类型，双击启动；如果 Truffle 已在运行，把项目路径转发给已运行实例并打开；允许多开的情况仅限 `TRUFFLE_ALLOW_MULTI=1` 调试。
- **扫描深度（原 Q14）**：默认目录只扫描第一层 `.truffle`，不递归。
- **低风险默认（未逐条询问，按此实现，用户可随时修改）**：外部项目只通过「导入」打开（原地打开，不复制）；同名项目在项目页显示完整路径/来源徽标；迁移后把 `session.json` 改名为 `session.json.migrated` 保留回滚；默认封面方式为「当前活动图」；4 图不足时重复最后一张。
