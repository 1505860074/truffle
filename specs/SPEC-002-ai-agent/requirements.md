> 文档编号：SPEC-002

> 状态：实现中（第一批核心已落地，待真实模型联调与后续工具补齐）

## 文档说明

本文档定义 Truffle 的 AI 修图 Agent 的架构、协议、指标、工具、风格系统与批量流程，是实现依据，不是完成证明。读者是后续实现该功能的 agent 或开发者。第 3 节是用户已确认、不得擅自更改的决策；第 4~11 节是实现细节；第 12 节列出尚未确认或需要实现时验证的问题。若与用户后续意见冲突，以用户最新意见为准，并更新本文档。不要重新引入 `.vbs` / `.ps1` 启动方式；项目启动仍使用 `.bat`。本文档中的流程图均为 ASCII 图，序号在文档内递增。

## 1. 背景与现状

当前 AI 修图链路（`src/truffle/agent/orchestrator.py`）：

```
用户一句话
  → 拼 system prompt（尺寸、人脸数、是否检测到人体、历史步骤、手动参数）
  → LLM 选择工具并直接给出参数（最多 10 轮）
  → registry.execute() 执行
  → 回填「工具执行成功」
  → 模型回复用户
```

现状问题：

- 模型默认收不到图片，只能看到极少量文字信息，无法判断画面状态；
- LLM 直接输出强度参数，没有量化依据，也没有结果验证；
- 工具执行后不回传指标变化，模型不知道是否过头；
- 没有持久 agent 状态，计划、目标、尝试过的参数都不保留；
- 多数工具是全局滤镜，缺少局部能力与工具副作用声明；
- 人脸/人体修饰靠“感觉”，没有可量化、可复现的指标。

## 2. 目标

1. 建立一个以「文字状态 + 本地求解器 + 评审闭环」为核心的 AI 修图 Agent；
2. LLM 只负责理解需求、选择风格、制定目标和选择工具；参数由本地求解器计算；
3. 支持多轮修改，每轮能看到编辑前后的量化变化；
4. 支持风格库（糖水、冷白、暖调、胶片、夜景、证件照等）和文字描述风格；
5. 支持 20 张以上的成套图：项目统一风格 + 每图可覆盖 + 一致性检查；
6. 支持朋友圈导出预设与 3×3 / N×N / 单张 / 自定义文本或头像的预览；
7. 保持现有工具 API 兼容，逐步重写内部实现；
8. Agent 的计划、指标、工具日志保存进 `.truffle`。

## 4. 总体架构

图 1：文字 LLM + 本地求解器

```
用户文字
  │
  ▼
① Intent / Style 解析（LLM）
   输出：style_id 或风格描述、目标指标、约束、允许工具集
  │
  ▼
② Perception（本地 CV）
   输出：全局指标、人脸指标、人体指标、质量指标、风格向量
  │
  ▼
③ Solver（本地，不经过 LLM）
   目标：风格距离 + 自然度 + 伪影代价 最小
   方法：规则初值 + 坐标下降 / 小范围搜索
  │
  ▼
④ Executor
   按顺序执行工具；记录每一步前后指标
  │
  ▼
⑤ Critic（本地 CV + 规则）
   判断目标是否达成、是否过头、是否有伪影
  │
  ├─ 未达成且预算未尽 → 回到 ③ 修参数
  └─ 达成或到上限 → 预览 + 解释 + 等待用户
```

图 2：20+ 张成套图

```
20+ 原图
  → 并行感知（本地，限制并发）
  → 项目基准（肤色/对比/饱和/色温中位数）
  → 一次 LLM 系列计划（风格、基准、每类图偏差）
  → 每张图本地求解参数
  → 一致性检查（用户设定强度）
  → 九宫格 / N×N 预览
  → 单张覆盖 / 批量导出
```

核心原则：

- **LLM 不猜数值**：LLM 输出目标与工具集，求解器算参数；
- **评审器不依赖 LLM**：用指标判断是否收敛；
- **风格是一等公民**：`StyleProfile` 决定目标区间，不每次从零猜；
- **每步可回放**：前后指标、参数、工具日志都持久化。

## 5. 文字状态协议

### 5.1 状态结构

`ImageState`（`schema = "state.v1"`）建议字段：

```json
{
  "schema": "state.v1",
  "image": {"w": 1920, "h": 1080, "scene": "indoor_warm", "subject": "portrait"},
  "tone": {
    "ev": 0.35, "contrast": 0.42, "wb_k": 5300, "tint": 0.05,
    "clip_hi": 1.2, "clip_lo": 0.4, "shadow": 0.12, "mid": 0.63, "high": 0.25
  },
  "color": {
    "sat": 0.38, "vib": 0.22, "colorfulness": 0.41,
    "skin_hue": 24.0, "skin_sat": 0.31, "skin_L": 68.0, "skin_a": 12.0
  },
  "faces": [{
    "id": "f1",
    "box": [x, y, w, h],
    "ratio": {
      "face_wh": 1.31, "jaw": 0.78, "cheek": 0.91, "chin": 0.18,
      "eye_w": 0.46, "eye_ar": 0.33, "nose_w": 0.34, "mouth_w": 0.52,
      "symmetry": 0.93, "third_upper": 0.31, "third_mid": 0.34, "third_low": 0.35
    },
    "skin": {
      "texture": 0.57, "redness": 0.21, "specular": 0.08,
      "blemish": 4, "under_eye": 0.34, "evenness": 0.74, "teeth_yellow": 0.18
    }
  }],
  "body": {
    "pose_conf": 0.91, "shoulder_hip": 1.12, "waist_hip": 0.81,
    "leg_body": 0.52, "symmetry": 0.94
  },
  "quality": {
    "sharp": 0.61, "noise": 0.18, "haze": 0.22,
    "artifact": 0.05, "oversmooth": 0.0, "warp_smooth": 0.0
  },
  "style_vec": {
    "warmth": 0.62, "airy": 0.71, "contrast": 0.34,
    "glow": 0.58, "cool_shadow": 0.21, "film": 0.12
  }
}
```

所有数值归一化到 0~1 或明确单位（EV、K、百分比）。缺失字段用 `null`，不要用 0 冒充。

### 5.2 文字编码

给 LLM 的 `system` 中放紧凑 JSON，不放自然语言长文。建议：

```
[IMAGE_STATE]
{"tone":{"ev":0.35,"contrast":0.42,...},"faces":[...],"body":{...},"style_vec":{...}}
[STYLE_TARGET]
{"id":"tangshui_01","targets":{"tone.contrast":[-0.18,-0.05],...}}
[CONSTRAINTS]
{"naturalness_min":0.7,"consistency":0.8,"identity_warning_only":true}
[ALLOWED_TOOLS]
color_adjust,color_temp,curves,hsl,skin_smooth,slim_face,...
```

### 5.3 输出解码

- 使用 OpenAI tool calling；计划也可用 `set_plan` 工具提交 JSON。
- 解码层必须：Schema 校验、类型转换、范围夹紧、失败修复/重试、原始输出日志。
- 不合法工具名 → 返回错误给模型，不中断会话。
- 所有日志写入项目 `agent.json`（见 10.3）。

## 6. 量化指标

### 6.1 全局指标

| 指标 | 计算思路 | 用途 |
| --- | --- | --- |
| `ev` | `log2(mean_luma / 128)` | 曝光 |
| `contrast` | 灰度标准差归一化 | 对比 |
| `sat` / `vib` | HSV 饱和度均值 / 低饱和像素提升潜力 | 色彩 |
| `wb_k` / `tint` | 灰度世界 + 高光/肤色偏移的近似估算 | 白平衡 |
| `clip_hi` / `clip_lo` | 各通道过曝/欠曝像素占比 | 剪切保护 |
| `shadow/mid/high` | 灰度直方图分段占比 | 影调分布 |
| `colorfulness` | Hasler-Süsstrunk 指标归一化 | 色彩丰富度 |
| `skin_hue/sat/L/a` | 皮肤掩膜内的 Lab/HSV 中位数 | 肤色统一 |
| `sharp` | Laplacian 方差归一化 | 锐度 |
| `noise` | 平坦区高频残差估计 | 噪点 |
| `haze` | 暗通道/对比度近似 | 去雾 |
| `artifact` | 色带、块效应、过曝边缘的启发式评分 | 评审 |

### 6.2 人脸指标

- 几何全部以瞳距（IPD）或脸高归一化；
- 指标：脸宽/脸高、下颌宽/颧宽、下巴长/脸高、眼宽/瞳距、眼睛纵横比、鼻宽/瞳距、嘴宽/瞳距、左右对称、三庭比例；
- 皮肤：纹理能量（高频残差）、泛红（Lab a）、高光占比、痘斑数量/面积、黑眼圈（眼下 L 差）、肤色均匀度、牙齿黄度；
- 不做唯一“颜值分”；指标只用于计算与风格目标的距离。

### 6.3 人体指标

- 基于 MediaPipe Pose 33 点；
- 肩宽/臀宽、腰臀比、腿长/身高、左右对称、姿态置信度；
- 不判断“胖瘦美丑”，只描述相对目标比例的偏离；
- 姿态缺失时返回 `null`，工具应安全跳过。

### 6.4 风格向量

`style_vec` 由本地 CV 计算，用来替代“让模型看图”：

- `warmth`：肤色/高光色温倾向；
- `airy`：高光柔和度 + 阴影提亮 + 低对比；
- `contrast`：影调反差；
- `glow`：高光溢出/柔光感；
- `cool_shadow`：阴影偏冷；
- `film`：褪色、颗粒、低饱和倾向。

## 7. 风格系统

### 7.1 StyleProfile

```json
{
  "id": "tangshui_01",
  "name": "糖水通透",
  "description": "高光柔和、低对比、肤色偏暖、轻微发光",
  "targets": {
    "tone.ev": [0.1, 0.4],
    "tone.contrast": [-0.18, -0.05],
    "tone.shadow": [0.12, 0.22],
    "color.sat": [0.35, 0.5],
    "color.skin_L": [66, 74],
    "quality.sharp": [0.45, 0.65]
  },
  "skin": {"smooth": [0.2, 0.45], "texture_keep": [0.6, 0.8]},
  "geometry": {"face_wh": [-0.05, 0.0], "jaw": [-0.04, 0.0]},
  "finish": {"vignette": [0.0, 0.15], "grain": [0.0, 0.08]},
  "constraints": {"naturalness_min": 0.72, "identity_warning_only": true}
}
```

内置风格（第一版）：`natural`、`tangshui`、`cold_white`、`warm_film`、`night`、`id_photo`、`high_sat_low_contrast`。后续可扩展。

### 7.2 风格距离

```text
distance = Σ weight_i * normalized_distance(current_i, target_range_i)
```

- 落在目标区间内距离为 0；
- 超出区间按区间宽度归一化；
- 权重来自 StyleProfile；人脸/肤色可单独加权；
- 一致性检查用项目基准与每张图的偏差。

### 7.3 风格推断

用户未指定风格时：

1. 本地场景分类（室内暖光/室外日光/阴天/夜景/逆光）；
2. 肤色、对比、饱和、色温特征；
3. 项目名称/主题/已有图片的多数风格；
4. 选择最接近的内置风格；无把握时用 `natural`。

## 8. 参数求解器

### 8.1 输入输出

- 输入：当前图像（预览分辨率）、`StyleProfile`、允许工具集、约束；
- 输出：`jobs: [(tool, params)]`、预期指标、评分、迭代日志。

### 8.2 方法

1. 规则初值：根据指标与目标区间差值给出初始参数（例如 `ev` → `color_adjust.brightness`）；
2. 坐标下降：对每个连续参数尝试 `±step`，渲染并评分，保留更优值；2~3 轮；
3. 评分函数：

```text
score = style_distance
      + λ1 * naturalness_penalty
      + λ2 * artifact_penalty
      + λ3 * over_edit_penalty
```

4. 只在预览分辨率搜索，最终应用到全分辨率；
5. 参数变化小于阈值时停止，避免反复无效编辑。

### 8.3 自然度 / 形变检查

- 不计算身份 embedding（A12）；
- 检查形变场平滑度、关键点位移、皮肤纹理保留率、噪点放大、色带、过曝；
- 形变强度超过灾难性阈值时停止并提示“已接近不自然”。

## 9. 评审器

每次编辑后输出：

```json
{
  "ok": false,
  "style_distance": 0.31,
  "naturalness": 0.68,
  "artifacts": ["skin_texture_loss"],
  "deltas": {"tone.contrast": -0.12, "skin.texture": -0.18},
  "suggestions": ["reduce skin_smooth strength", "raise shadow slightly"]
}
```

评审器只依赖指标与规则，不调用 LLM。结果以 tool message 回填给模型，模型决定是否继续。

## 10. Agent 协议与会话

### 10.1 工具分层

| 类型 | 作用 | 示例 |
| --- | --- | --- |
| Observe | 只读，返回状态 | `inspect_image`、`inspect_face`、`inspect_body`、`compare_state` |
| Edit | 改像素 | `color_adjust`、`curves`、`skin_smooth`、`slim_face` |
| Meta | 控制会话 | `set_style`、`apply_style`、`ask_user`、`undo_last` |

`apply_style` 是求解器入口：模型给风格 id 和目标，求解器算参数并执行。

### 10.2 多轮流程

1. 解析用户需求 → 选风格/目标；
2. 读取当前 `ImageState`；
3. 选工具集 → 调用 `apply_style` 或普通工具；
4. 执行 → 评审 → 把 `Critique` 回填；
5. 未达标且预算未尽 → 求解器继续修参数；
6. 达标 → 回复用户；用户不满意 → 下一轮。

### 10.3 持久化

在 `.truffle` 内保存 `agent.json`：

```json
{
  "schema": 1,
  "project_style": "tangshui_01",
  "consistency": 0.8,
  "images": {
    "img_0001": {
      "style_override": null,
      "last_state": {...},
      "last_plan": {...},
      "logs": [{"turn": 1, "before": {...}, "after": {...}, "jobs": [...]}]
    }
  }
}
```

由 `Project.save` 打包；打开项目时恢复。

## 11. 批量与导出

### 11.1 批量规划

- 并行感知，限制并发（CPU 核数/内存）；
- 项目基准：肤色 L/a、对比、饱和、色温的中位数；
- 一次 LLM 系列计划，输出每张图的允许偏差；
- 每张图本地求解；
- 一致性强度用户可调（0=不限制，1=严格）。

### 11.2 预览

- 3×3 或 N×N 拼图；
- 单张预览；
- 自定义文本或用户头像作为拼图中心/角标；
- 可点单张覆盖风格或重新生成。

### 11.3 导出

- 朋友圈预设：1080p 长边、3:4/4:3、JPEG 质量、文件名序号；
- 支持九宫格拼图导出和单张导出；
- 水印可选。

## 12. 工具清单与缺口

现有 25 个工具保留 API。需要补齐：

- 基础影调：曝光、色阶、白平衡（色温+色调）、自然饱和度、分离色调、LUT；
- 局部：矩形/椭圆/径向/线性渐变蒙版、局部参数应用；
- 修复：污点半径/强度、克隆、减淡加深；
- 面部：面部光影、眼白、虹膜、牙齿、头发；
- 人体：肩腰胯、腿长、姿态；
- 背景：虚化、替换、去杂物；
- 观察：全局/人脸/人体/区域/前后对比。

每个新工具必须声明：前置条件、影响的指标、自然度代价、最大强度、耗时等级。

## 13. 风格配方学习

1. **学目标分布**：收集好看图片 → 提取 `style_vec`/色调/肤色/对比 → 聚类成风格目标；
2. **自监督学配方**：用求解器把源图调到风格目标，记录 `(指标, 参数)` 对；
3. **训练小模型**：GBDT/MLP/ONNX，输入指标，输出参数初值；
4. **运行时**：小模型给初值，求解器做局部修正；
5. 不使用用户数据上传；如需个性化，仅当前项目内临时记录。

## 14. 性能

- 预览最长边 ≤ 1024；最终全分辨率应用；
- 指标与人脸/姿态按图像身份缓存；
- 批量并发受 CPU/GPU 内存限制；
- ONNX Runtime：CUDA 优先，CPU 回退；缺少 GPU 不阻塞功能；
- 目标：单图预览求解 < 2s（CPU 中等配置），批量 20 张 < 5 分钟（不含 LLM 往返）。

## 15. 验收标准

- [ ] LLM 不再直接猜参数；`apply_style` 由求解器输出参数；
- [ ] 至少 6 个内置风格可选出预览；

- [ ] Agent 状态写入 `.truffle` 并可恢复；
